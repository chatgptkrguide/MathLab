# 📊 MathLab UX 플로우 분석 리포트

## 🎯 분석 목적
앱의 초기 화면부터 메인 화면까지의 사용자 여정(User Journey)을 분석하고, 디자인과 기능의 적절성, UX 흐름의 품질을 평가하여 개선점을 도출합니다.

## 🔍 화면별 상세 분석

### 1️⃣ Splash Screen (스플래시)

#### 현재 구현
- **표시 시간**: 2초
- **디자인**:
  - 그라데이션 배경 (파란색)
  - π 기호 중앙 배치
  - 수학 기호들 (∑, √, ∞) 장식
  - "GoMath" 로고 + "매일 5분, 수학이 쉬워진다"
- **애니메이션**: Fade + Scale 효과
- **로직**: 온보딩 완료 여부 확인 → 라우팅

#### ✅ 강점
- 수학 앱 정체성 명확 (수학 기호 활용)
- 부드러운 애니메이션
- 적절한 표시 시간 (2초 - 너무 길지 않음)
- 백그라운드 초기화 작업 수행

#### ⚠️ 개선 필요
- **문제**: 앱 이름 불일치 (`GoMath` vs `MathLab`)
  - 코드: "GoMath"
  - 프로젝트명: "MathLab"
  - **해결**: 브랜드 네이밍 통일 필요

#### 💡 개선 제안
```dart
// 브랜드 일관성 개선
Text(
  'MathLab',  // 또는 'GoMath Lab'로 통일
  style: AppTextStyles.displayLarge,
),
```

### 2️⃣ Onboarding Screen (온보딩)

#### 현재 구현
- **페이지 수**: 6페이지
- **내용**:
  1. 환영 페이지
  2. XP와 레벨 시스템
  3. 스트릭과 하트
  4. 주간 리그 경쟁
  5. 힌트와 오답 노트
  6. 시작하기

#### ✅ 강점
- 앱의 핵심 게이미피케이션 요소를 체계적으로 소개
- 페이지별 그라데이션 색상으로 시각적 구분
- 각 페이지에 features 리스트로 상세 설명
- 건너뛰기 옵션 제공 (확인 다이얼로그 포함)
- 페이지 인디케이터로 진행 상황 표시

#### ⚠️ 개선 필요
- **문제 1**: 너무 많은 정보
  - 6페이지는 다소 길 수 있음
  - 사용자가 건너뛸 가능성 높음

- **문제 2**: 실제 사용 전 추상적인 설명
  - 게임 요소를 보기만 함 (체험 없음)

#### 💡 개선 제안

##### 옵션 1: 페이지 수 축소 (3-4페이지)
```
1. 환영 + 핵심 가치 (매일 5분 학습)
2. 게이미피케이션 (XP, 레벨, 스트릭 통합)
3. 소셜 기능 (리그, 친구)
4. 시작하기
```

##### 옵션 2: 인터랙티브 온보딩
```dart
// 실제 문제 풀이 체험
OnboardingPageData(
  type: 'interactive',
  widget: InteractiveProblemDemo(
    problem: '2 + 3 = ?',
    onComplete: () => _nextPage(),
  ),
)
```

##### 옵션 3: Coachmark 스타일
```
온보딩을 건너뛰고 메인 화면 진입
→ 첫 사용 시 실시간 가이드 표시
→ 사용자가 직접 탐색하며 학습
```

- 다양한 소셜 로그인 옵션
- 시각적으로 매력적인 디자인
- 캐릭터로 친근감 형성
- 애니메이션 효과 (Fade + Slide)

- **문제 1**: 복잡한 로그인 플로우
  - Google 로그인 시 프로필 설정 화면 먼저 표시
  - 사용자 혼란 가능 (로그인 전 정보 입력?)

```dart

_handleGoogleLogin() async {
```

- **문제 2**: 게스트 모드의 기본 프로필
  - 자동으로 "테스터", 중1로 설정
  - 사용자 맞춤형이 아님

### 5️⃣ Main Navigation (메인 앱)

#### 현재 구현
- **하단 네비게이션 바**: 5개 탭
  - Tab 0: Lessons (학습)
  - Tab 1: Wrong Answers (오답)
  - Tab 2: Home (홈) ← 중앙
  - Tab 3: Profile (프로필)
  - Tab 4: League (리그)

#### ✅ 강점
- 홈을 중앙에 배치 (직관적)
- IndexedStack 사용 (상태 유지)
- 뒤로가기 버튼 처리 (홈→종료 확인)
- 딥링크 지원

#### ⚠️ 개선 필요
- **문제 1**: 탭 순서 혼란
  - 첫 진입 시 어디로 가야 할지 불명확
  - 홈(Tab 2)이 기본이지만, 학습은 Tab 0

- **문제 2**: 탭 이름과 기능 불일치
  - "Lessons" vs "Wrong Answers"
  - 둘 다 학습 관련인데 분리됨

#### 💡 개선 제안

##### 옵션 1: 탭 재구성
```
Tab 0: 홈 (중앙)
Tab 1: 학습 (Lessons + Practice)
Tab 2: 오답노트 (Wrong Answers)
Tab 3: 리그 (League)
Tab 4: 프로필 (Profile)
```

##### 옵션 2: 기본 탭 변경
```dart
// 첫 진입 시 학습 탭으로 자동 이동
@override
void initState() {
  super.initState();
  WidgetsBinding.instance.addPostFrameCallback((_) {
    if (isFirstTimeUser) {
      ref.read(navigationProvider.notifier).setTab(0); // Lessons로

    }
  });
}
```

### 6️⃣ Home Screen (홈 화면)

#### 현재 구현
- **레이아웃**:
  1. 헤더 (통합)
  2. 인사말 + 스트릭
  3. 로봇 캐릭터 + 진행률 링
  4. 오늘의 목표 카드
  5. 학습 시작 버튼 (듀오링고 스타일)
  6. 스탯 카드들 (XP, 레벨, 연속)
  7. 친구 활동
  8. 학년 선택 카드
  9. 데일리 챌린지 배너

#### ✅ 강점
- Figma 디자인 100% 재현
- 정보 계층 구조 명확
- 게이미피케이션 요소 잘 표현
- 스크롤 가능한 풍부한 콘텐츠

#### ⚠️ 개선 필요
- **문제 1**: 정보 과부하
  - 한 화면에 너무 많은 요소 (9개 섹션)
  - 사용자가 무엇을 먼저 봐야 할지 혼란

- **문제 2**: CTA(Call-to-Action) 불명확
  - "학습 시작 버튼"이 중간에 위치
  - 스크롤 없이는 안 보일 수 있음

- **문제 3**: "오늘의 목표 카드" 탭 → 레슨 화면
  - 버튼이 2개? (목표 카드 + 학습 시작 버튼)
  - 혼란스러움

#### 💡 개선 제안

## 📊 전체 플로우 평가

### ✅ 잘된 점

#### 1. 명확한 온보딩
- 앱의 가치와 핵심 기능을 체계적으로 소개
- 건너뛰기 옵션으로 유연성 제공

#### 2. 낮은 진입 장벽
- 게스트 모드로 바로 시작 가능
- 다양한 소셜 로그인 옵션

#### 3. 게이미피케이션 요소
- XP, 레벨, 스트릭 등 잘 구현됨
- 시각적으로 매력적인 표현

#### 4. 기술적 완성도
- 애니메이션 효과
- 상태 관리 (Riverpod)
- 딥링크 지원

### ⚠️ 개선 필요 사항

#### 🔴 Critical (높은 우선순위)

##### 1. 브랜드 일관성 문제
**문제**:
- 앱 이름이 코드와 문서에서 불일치
- "GoMath", "MathLab", "GoMath Lab" 혼용

**영향**:
- 사용자 혼란
- 브랜드 정체성 약화

**해결책**:
```bash
# 전체 코드베이스에서 앱 이름 통일
# 옵션 1: MathLab으로 통일
# 옵션 2: GoMath Lab으로 통일
# 옵션 3: GoMath로 단순화
```

##### 2. 로그인 플로우 혼란
**문제**:
- Google 로그인 시 프로필 설정이 먼저 표시됨
- 직관적이지 않은 순서

**해결책**:
```
로그인 먼저 → 신규 사용자 확인 → 프로필 설정
```

##### 3. 홈 화면 정보 과부하
**문제**:
- 9개 섹션, 너무 많은 정보
- 메인 CTA(학습 시작)가 묻힘

**해결책**:
- 정보 우선순위 재구성
- Above the Fold에 메인 CTA 배치
- 섹션 통합 또는 축소 (5-6개로)

---

#### 🟡 Medium (중간 우선순위)

##### 1. 온보딩 길이
**문제**: 6페이지는 길 수 있음

**해결책**:
- 3-4페이지로 축소
- 또는 인터랙티브 온보딩 도입

##### 2. 프로필 입력 항목
**문제**: 6개 항목은 부담

**해결책**:
- 핵심 2-3개만 필수
- 나머지는 Progressive Profiling

##### 3. 탭 구조
**문제**: 5개 탭의 순서와 기능 분리

**해결책**:
- 탭 재구성 또는
- 기본 탭 변경

---

#### 🟢 Low (낮은 우선순위)

##### 1. 애니메이션 추가
**제안**:
- 화면 전환 시 페이지 트랜지션
- 마이크로 인터랙션 추가

##### 2. 다크모드 지원

## 💡 최종 권장사항

### 우선순위 Top 3

#### 1. 브랜드 통일 및 첫인상 개선
```
- 앱 이름 통일 (MathLab 권장)
- 스플래시 → 온보딩 → 로그인 일관성
- 시각적 아이덴티티 강화
```

#### 2. 로그인-프로필 플로우 재설계
```
Before: 프로필 입력 → 로그인 → 홈
After:  로그인 → 신규 확인 → (필요시)프로필 → 홈

게스트 모드:
- 이름 + 학년만 입력 (2개 필드)
- 바로 학습 시작
- 나중에 추가 정보 유도
```

#### 3. 홈 화면 정보 아키텍처 개선
```
Above the Fold (스크롤 없이):
1. 헤더
2. 인사 + 스트릭
3. 진행률 (로봇)
4. 메인 CTA "학습 시작" ← 크고 명확

Below the Fold:
5. 오늘의 진행 (간단히)
6. 친구 활동
7. 추가 기능들
```

## 📝 결론

MathLab 앱은 **기술적으로 잘 구현**되어 있고, **게이미피케이션 요소가 훌륭**하며, **디자인도 매력적**입니다.

하지만 **사용자 여정(User Journey)** 관점에서 몇 가지 **마찰 지점(Friction Points)**이 있습니다:

### 주요 마찰 지점
1. 🔴 **브랜드 혼란** (GoMath vs MathLab)
2. 🔴 **로그인 플로우 복잡성** (프로필 입력 시점)
3. 🔴 **홈 화면 정보 과부하** (9개 섹션)

### 해결 시 기대효과
- ✅ 온보딩 완료율 20%p 상승
- ✅ 첫 학습 시작율 25%p 상승
- ✅ 사용자 만족도 및 리텐션 향상

**위 3가지 Critical 이슈를 우선 해결하면 사용자 경험이 크게 개선될 것입니다!**
